What You Are Adding

Two Separate API Credentials
You must configure two separate Cloudflare Workers AI accounts. Each has its own Account ID and its own API Token. They are separated by task type.

The first account is dedicated to text generation. It handles all language model inference: content writing, replies, summaries, strategy logic, and reasoning.

The second account is dedicated to image generation. It handles all image model inference: post graphics, social visuals, and product imagery.

This separation exists for two reasons. First, each account gets its own independent 10,000 Neuron daily allocation, which doubles the total free capacity. Second, it prevents image generation from starving text generation on a busy day, and vice versa. The two workloads do not compete for the same quota.

Both accounts must be treated the same way the existing free mode accounts are treated. They are part of the rotation pool. They are consumed, monitored, and failed over from exactly like every other account already in the system.

Error Handling and Failover
The Cloudflare API returns specific errors that the router must understand.

A 429 with an error code indicating rate limiting or daily allocation exhaustion means the account is out of Neurons for the day. The router must mark that account as exhausted and move to the next account in the pool, exactly as it does for any other provider that hits a limit.

A 401 or 403 means the account credentials are invalid or revoked. The router must mark that account as unhealthy and alert the admin, then move to the next account.

A 400 with a model error means the requested model is not available on the free plan or is misspelled. The router must log this and fall back to the default model for that task type.

Any other error must be handled by the existing error handling and dynamic problem solving logic already implemented in Adirum AI. Do not hard-code new error handlers. Route the errors through the existing pipeline.
